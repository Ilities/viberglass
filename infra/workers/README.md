# Worker Images

Docker images for Viberator workers.

## Images

Generated by `npm run generate:dockerfiles` from the harnesses' fragments and the templates in `docker/base/`; don't edit them by hand.

| Dockerfile | Agent | Notes |
|---|---|---|
| `base/base-worker.Dockerfile` | none | Base image and template for the Debian images |
| `base/lambda-worker.Dockerfile` | none | Template for the Lambda image |
| `viberator-worker-multi-agent.Dockerfile` | all agents | All CLIs pre-installed; also the local Docker image |
| `viberator-ecs-worker.Dockerfile` | the default agent | Not used by runners; ECS runners pull the harness images |
| `viberator-lambda.Dockerfile` | all agents | Lambda |
| `generated/<variant>.Dockerfile` | one agent each | `FROM` the base image |

## Published images

`publish-worker-images.yml` builds the base image and each harness's default image for linux/amd64 and linux/arm64 on every push to `main` and on releases, and pushes them to GHCR (`ghcr.io/<owner>/viberator-...`) tagged `latest`, the commit sha and, on a release, its tag. Docker, Kubernetes and ECS runners pull these by default.

`deploy-viberators.yml` pushes to ECR with the script below. On a push to `main` it builds only the Lambda image; run it by hand with `all` or one harness to fill ECR with the harness images too. Each run pushes `latest` and the commit sha (or the tag you enter).

To run ECS runners from your own ECR instead of GHCR, set `viberglass:workerImageRegistry: ecr` in the platform stack, push the harness images with `./scripts/setup-harness-images.sh <env> all`, run `pulumi up` in `infra/platform` and deploy the backend. `viberglass:workerImageTag` pins the tag (default `latest`).

## Build & Push to ECR

One command sets up all repos, builds, and pushes:

```bash
./scripts/setup-harness-images.sh dev   # or prod
./scripts/setup-harness-images.sh dev multi-agent  # specific image only
```

Or manually:

```bash
./scripts/build-workers.sh all
./scripts/push-workers.sh all
```

## Image Selection

Workers get the default image for the runner's harness from the worker image catalog: `<VIBERATOR_WORKER_REGISTRY>/<repository>:<VIBERATOR_WORKER_IMAGE_TAG>` for Docker, ECS and Kubernetes, and the workers stack's `viberator-lambda-worker:latest` for Lambda. Override it in the runner's deployment config with `containerImage` (Docker, ECS, Kubernetes) or `imageUri` (Lambda).
